## 推送 GitHub 代理排查（关键！）
- **现象**：沙箱 git push 一直失败（CONNECT tunnel 502 / SSL EOF / 直连超时）。浏览器能上 GitHub 正常。
- **根因**：WorkBuddy 沙箱 egress 代理 `127.0.0.1:62099` 已宕机（连 example.com 都瞬时 000）；
  沙箱禁止直连 egress（--noproxy 也超时）。git 无显式 proxy 配置、无 proxy 环境变量，但出口被强制走 62099。
- **可用代理**：`127.0.0.1:10808`（宿主机浏览器/VPN 实际走的代理，沙箱内可连）能正常转发 GitHub
  （curl -x 返回 200，git 经它隧道 200）。**这是修复关键**。
- **修法（有效）**：`git -c http.proxy=http://127.0.0.1:10808 push`（仅设环境变量 HTTPS_PROXY 不生效，
  必须 `-c http.proxy` 显式指定）。已成功推送 5 个提交到 origin/feat/login-credential（7a08f6e..66b420b）。
- ⚠️ **沙箱限制**：`refs/remotes/origin/*` 写入被回滚（update-ref 返回成功但不落盘），
  故 `git status` 仍显示 `origin/feat/login-credential [gone]`、`git rev-parse origin/...` 报 unknown revision。
  **这是展示层假象，不影响已推送结果**（ls-remote 权威确认远程已含全部提交）。勿反复尝试修复该引用。
- 后续推送复用：每次 `HTTPS_PROXY=http://127.0.0.1:10808 HTTP_PROXY=http://127.0.0.1:10808 git -c http.proxy=http://127.0.0.1:10808 <cmd>`。

## 排查：/rbac 与 /rbac/permissions 两页"完全一样"（15:35）
- **结论：功能上确实完全一样**。`rbac/index.astro` 与 `rbac/permissions/index.astro` 除 3 处外逐字节相同：
  页守卫码（`SYSTEM_ROLE_MANAGE` vs `SYSTEM_PERMISSION_MANAGE`）、`activeNavItem`（`RBAC` vs `RBAC_PERMISSIONS`）、
  i18n 键（`pageTitle.rbac` "角色与权限" vs `pageTitle.rbacPermissions` "权限配置"）。正文同为
  `readRbacBoard(env.FEED_DB)` + `<RbacApp client:only="react" initialBoard={board} />`。
  `RbacApp` 只吃 `initialBoard`、完全不感知查看者权限 → 两页渲染同一个角色编辑器。
- **重复原因（B27，功能审计 spec.md:363-364/604-606）**：`ext_menu.permission_code` 一行只绑一个码，
  `menu.ts:77` 按该单码过滤菜单 → 只持 `system:permission:manage` 的账号没有导航入口，
  而存授权的 `POST /ajax/rbac/role-permissions` 恰恰要这个码。方案选了"新增菜单行+新页、一菜单一码"，
  而非放宽校验。**已 deploy9 落库（迁移 0061），生产已存在两页**。
- **由此产生的真实缺陷（3 条）**：
  ① 两个页面各自只对"持双码者"完整可用：role:manage 单持者能进 `/rbac` 但存授权 403；
     permission:manage 单持者能存授权但角色 CRUD（create/rename/delete 全绑 role:manage）403。
     复制了页面，没复制能力。
  ② SSR 侧门：`/rbac/permissions` 页守卫只要 permission:manage，却在服务端直接 `readRbacBoard`
     返回全量 board（角色、授权、权限目录）——同一份数据走 `GET /ajax/rbac` 却要 role:manage。
  ③ `admin-page-guards.test.ts` **红了**（已实跑确认）：该测试只从 `migrations/0041_ext_menu.sql` 读菜单行，
     新行在 0061 → `system:permission:manage` 不在 bound 集合，断言
     "never guards a page with a code no menu binds" 失败于 `rbac/permissions/index.astro`。
     （`/rbac/audit` 因绑 role:manage 侥幸通过。）
- 附带发现：`ADMIN_URLS.ajaxRbacBoard` + `getAdminRbacBoard` 全仓零调用（死代码，RbacApp 只 POST）。
