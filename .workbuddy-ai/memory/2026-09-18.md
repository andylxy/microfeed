## 2. 首页顶部布局真正的病根：`html { max-width: 70ch }`

之前只改了 `.fq-*` 的 CSS，但页面仍被挤成 ~604px 窄条，`登录/注册` 竖排折行。
真凶在共享样式表 `microfeed-compiled-styles`：

```css
html { max-width: 70ch; margin: auto; padding: 1.5em 0.2em; }
```

`70ch` ≈ 604px，`.fq-header{width:100%}` 只能 = 604px。修法（feed-zh 专属）：

```css
html:has(.fq-header) { margin: 0 !important; max-width: none !important; padding: 0 !important; }
```

连带两处必须同步改，否则会崩：

- `.mf-reader-page { margin: -2em auto -4em }` 原本是用来抵消 html 的 padding，
  改成 `margin: 0 auto`，否则阅读页会被顶到视口上方裁掉。
- 页面根 `.mf-book-detail-page/.mf-library-page/.mf-reader-page` 原来用
  `width:100vw` + `margin:±(50%-50vw)` 逃逸 70ch；html 全宽后 `100vw` 会因竖向滚动条
  多出 ~15px 横向滚动条，改成 `width:100%` 并删掉负 margin。

修复后实测：header 1409px 全宽、`.fq-header-inner` 1200px 居中、auth 单行 25px、
`docScrollW === htmlW`（无横向滚动）。

## 3. 章节阅读页全 404 的两个数据 bug（`执行修正`）

`/i/<slug>-<id>/`、`/json/<slug>/`、`/rss/<slug>/` 全 404，但书本页能列出章节。

- **Bug A：章节 id 只有 10 位。** `getIdFromSlug` 只认 `/[\d\w\-_]{11}$/`，10 位
  slug 解析出 `undefined` → 查询退化成 `id = '__missing_item__'` → 404。
  18 个种子章节（`Bh01CjTxXx` 等）都是 10 位；主书章节 `XhJgChAMmmm` 是 11 位，
  所以主书阅读页一直正常。**判据**：`length(id) <> 11`。
  修：`.microfeed/fix-chapter-ids.sql` 给每个 id 追加 `0` 补到 11 位。
  改前先确认没有其它表引用：`item_create_idempotency` / `ext_content_audit` /
  `ext_content_report` 对这些 id 都是 0 行（种子是直接 INSERT 进 items 的，绕过了服务层）。
- **Bug B：正文写在 `content_html` 而不是 `description`。** microfeed 的 item 正文
  存在 `data.description`（HTML），`content_text` 是派生的纯文本；公开 JSON 构建器
  用 `content_html = item.description` 喂给阅读模板。种子把正文写进 `data.content_html`
  → 阅读页正文区空白。修：`.microfeed/fix-chapter-content.sql` 把
  `content_html` → `description` 并补 `content_text`（种子 HTML 只有 `<p>…</p>`，
  用 replace 去标签即可）。
- 两个种子文件已同步改正，避免重跑种子时把旧 id/旧字段又插回去。

## 11. 第 4 批（数据）途中挖出两个真 bug

摸数据时发现主书「星河剑歌」的目录顺序和阅读页目录都是坏的，比原计划的数据项严重得多。

**Bug A — 目录按卷交错**：`chapterNo` **按卷重置**（第一卷 第1章 与 第三卷 第1章 都是 1），
而 `getBookChapters` 与 `book/[id]` 路由都只按 `chapterNo` 排序 → 线上目录变成
第一章 → 第三卷 第1章 → 第二章 → 第二卷 第2章 → …（三卷交错）。
`_microfeed.order` 也是按卷重置的，**不能用**；**`pub_date` 才是全局单调的连载顺序**
（第一卷 01-10..15、第二卷 02-02..05、第三卷 03-01..04）。
修：两处排序都改为「pub_date 升序，chapterNo 破同日并列」；
`getBookChapters` 额外在顶层输出 `date_published`（对齐公开 feed 的 item 形状，
让消费方能排序而不用掏 `_microfeed`）。

**Bug B — 阅读页目录只剩 1 章、上下章同时「已是第一章/已是最后一章」**：
阅读页用 `chapterFeed = loadPublishedFeed({status__in})` 建目录，那是**主 feed 的分页窗口**
（`itemsPerPage`，按最新倒序），过滤出本书后往往只剩当前章。
修：改用 `getBookChapters(db, bookId, origin)` 直查（与书本页一致），
顺序天然正确。**教训：凡是「按 bookId 取整本书章节」的需求，一律走 `getBookChapters`，
不要用 feed 的分页窗口。**

**wordCount**：星河剑歌原本没有 `_microfeed.wordCount`。它 14 章的实际字数合计只有 **799**
（每章 30-190 字，内容本身就是这么短），所以按真实值补 799（与详情页的 totalWordCount 一致）。
⚠️ 注意样本书是「3 章 × ~750 字」但频道 `wordCount` 写 52-124 万 —— 样本书的这个字段是
**装饰性/编辑值**，与章节合计差约 380 倍。要让全站口径一致，得二选一：把样本书改成真实合计，
或把主书章节内容加长。已报告，未擅自动。

**cat_x1 规范化：不做**。它已不再对外展示；规范化要改 `ext_category.id` + 4 行
`channels.genre` + 4 处 `data._microfeed.genre`，零用户收益却有丢关联风险。建议保留。
