# 006 工单复验：书↔卷章↔正文 关联根因（基于真实端点 + 源表实测）

> 用户原话：导入后「动态标签、书名、卷节、正文」关系没匹配上；书↔卷章没匹配对，
> 卷章↔正文没匹配对，导入的书没有「卷」信息。
>
> 本文不靠数据模型推断，而是（a）实际走通移动端取数链路（见 `endpoint-flow.md`），
> （b）直接读源 `ctwh/{WorkInfo,Book,BookBody}.sql` 的真实关联键，得出可验证结论。

### 三个没有章节的书（直查 `Book.sql` 确认）
- `BookNo=100100`（针灸大成）、`9010000`（针灸篇・人纪）、`9030000`（黄帝内经・人纪）

## 2. 三条关系逐条判定（用 `endpoint-flow.md` 的线上实测佐证）

### 2.1 书 → 卷章（频道 `book_id` ↔ 篇章）— 10/13 正确，1 本名实不符，3 本源缺
- 正确：难经 / 素问 / 灵枢 / 神农本草经疏 / 伤寒杂病论桂林古本 / 伤寒论人纪 / 神农人纪 / 金匮人纪 / 金匮要略宋版（线上实测都有对应章数）。
- **名实不符**：`伤寒金匮・(宋版)` 频道挂的是 `BookId=10001` 的 27 篇**伤寒论**内容（首章
  「赵开美翻刻宋板《伤寒论》」）。根因：源把「伤寒金匮」(WorkInfo.BookNo=10001) 与
  「伤寒论」(Book.BookId=10001) 复用同一编号，导入按编号关联 → 书名与内容错位。金匮内容
  本身在 `金匮要略・(宋版)` 频道，未丢。
- **源缺**：针灸大成 / 针灸篇人纪 / 黄帝内经人纪 三本在源 `Book` 表无篇章行 → 线上 0 章。

### 2.2 卷章 → 正文（篇章 `tcm_parent_id` ↔ 条文）— 正确
- 源 `BookBody.BookInfoId` 与 `Book.BookInfoId` 共用同一全局主键空间，
  `build.ts` 按 `BookInfoId` 把条文挂到对应篇章（`chapterIdBySource`）。
- 线上实测：金匮要略宋版首章「脏腑经络先后病」回 17 条，条文内容为该章正文（含 `$a{}` 标记原样），
  `GetChapterContent` 的 `data[].data` 正确返回。孤儿条文数此前核查为 0。
- → 这条关系**没问题**，用户感知的「卷章和正文没匹配对」源于 2.1 的书名错位（整本挂错内容）。

### 2.3 分类 → 书（频道 `genre` ↔ 分类）— 正确
- `getAppNav` 用 `ext_category.id = channels.genre` JOIN，线上返回 6 分类 20 书，与源 WorkInfo 一致。

## 3. 修复方案（脚本侧可做的）

| 问题 | 是否脚本 bug | 修复动作 |
|---|---|---|
| 伤寒金匮/伤寒论 名实不符 | 否（源编号冲突），但可修正 | 在 `build.ts` 加 `BOOK_NAME_OVERRIDE`，把 `BookNo=10001` 的频道名正名为「伤寒论・(宋版)」（内容本来就是伤寒论；金匮在另一频道）。**需用户确认是否采用此正名**（若要对齐 netcoer 原样显示「伤寒金匮」，则不改）。 |
| 三本中医书 0 章 | 否（源缺篇章） | 脚本无法凭空造章。在导入报告里**显式告警**「有书无章」的 WorkInfo 条目，便于发现源缺口；并提醒补充完整源 `Book.sql`。 |
| 卷章↔正文 | 否，已正确 | 不动。 |
