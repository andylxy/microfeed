## 0. 一分钟结论（全部来自实际数据）

| 问题 | 实际答案 |
|---|---|
| 卷是表吗？ | **不是**。实际书里卷只存在于每章 `data._microfeed.volume` 字符串上；实际共 3 个卷名 |
| 卷怎么和书关联？ | **卷没有独立存在**——卷的归属 = 承载它的章的归属。章通过「书键双写」挂在书上，卷名随之属于该书 |
| 章怎么和书关联？ | **双键**：`items.book_id` 列（0056 迁移加的索引列）+ `data._microfeed.bookId` 标签，实际 15 章两处一致 |
| 章节号是什么？ | **卷内序号**。实际：第一卷 1-6、第二卷 2-5（缺 1，原因见 §3）、第三卷 1-4，每卷独立从 1 计数 |
| 阅读顺序靠什么？ | `pub_date`。实际数据每日一章（2026-01-10 → 03-04），公开书页平铺按它升序 |
| 正文存哪？ | `data.description`（HTML）；实际 15 章 `content_format` 全部省略 = 缺省 HTML |

## 0.5 必填还是可选？（系统强制 ≠ 效果强制）

API Schema（`ApiSchemas.ts`，`.loose()`）**所有字段 optional**；库里空标题空正文草稿（`RLhsPgdL3U2`/`KQ3_PkVlVGe`）实证。所以「必须有」都是**效果强制**：

| 字段 | 写入层强制？ | 不写的实际后果 | 结论 |
|---|---|---|---|
| 书 `data.title` | 否 | 显示 untitled | 必须有 |
| 章 title | 否 | 后台「未命名章节」 | 必须有 |
| 正文 `data.description` | 否 | 阅读页空白、搜不到 | 发布前必须有 |
| `pub_date` | 否 | **阅读顺序崩**（空值排最前） | 必须填 |
| `_microfeed.volume` | 否 | 后台「未归卷」桶垫底（实际书 3 条草稿正如此） | 开卷必须逐字一致 |
| `_microfeed.chapterNo` | 否 | 后台按 0 排最前 | 强烈建议（规范 §0.6） |
| `content_format` | 否 | 缺省即 HTML（`BodyFormat.ts:17`） | 可不填 |

## 0.6 章节序号（chapterNo）规范——按实际书执行

实际书 15 条正式章 **章号 = 标题章号 15/15 一致**，规则即从此提炼：

1. **卷内序号**，从 1 起，每卷独立计数（实际：第二卷从 2 开始是因为第 1 章还是未归卷草稿；第三卷重新从 1 起）。
2. **必须 = 标题「第Y章」的 Y**（实际 15/15，如 `第二卷 第4章 剑阵` ⇔ `chapterNo: 4`）。
3. **同卷唯一**、连续不跳号（实际三卷均连续）。
4. **不是全局顺序**——全局只看 `pub_date`；chapterNo 仅公开页「同日」决胜 + 后台卷面板卷内主排序。
5. 缺省按 0 处理必乱序，**不许省略**。

## 0.7 关联匹配三键（实际书实现，加章必须三键齐）

| 键 | 落点 | 实际值（本书） | 匹配要求 |
|---|---|---|---|
| **书键（双写）** | `items.book_id` 列 + `data._microfeed.bookId` | 都 = `J1jGJjUWeCz` | 两处**同时写、必须一致**（审计 15/15） |
| **卷键** | `data._microfeed.volume` 字符串 | `第一卷 初入江湖` / `第二卷 星河初现` / `第三卷 归墟之门` | 同卷各章**逐字一致**（含空格）；卷只属于写它的书，跨书同名互不相干 |
| **序号键** | `data._microfeed.chapterNo` | 见 §3 各卷序列 | = 标题章号；同卷唯一连续 |

> 游离反例（实际存在）：2 条空草稿两个书键都是 NULL——完全没归属书，后台卷面板看不到它们；这 就是「章必须归属书本」不做会发生什么。

## 1. 三层数据模型（比喻版 + 实际数据）

**文件柜**：书 = 抽屉（Channel 一行）；卷 = 贴在文件上的标签（不是隔板）；章 = 一份文件（Item 一行）。

书频道 `channels.data`（实际）：

```json
{
  "title": "星河剑歌",
  "description": "少年陆尘持一柄断剑，自边陲小城走出，踏碎星河。",
  "authors": [{ "name": "墨青" }],
  "genre": "cat_x1",
  "_microfeed": { "serialStatus": "serializing", "signStatus": "signed",
                  "genre": "cat_x1", "tags": ["热血","升级","剑道"], "wordCount": 799 }
}
```

章 `items.data`（实际，XhJgCh8Hhhh）：

```json
{
  "title": "第二卷 第2章 星火",
  "description": "<p>……</p>",
  "_microfeed": { "volume": "第二卷 星河初现", "chapterNo": 2, "order": 2,
                  "wordCount": 39, "reviewStatus": "approved", "bookId": "J1jGJjUWeCz" }
}
```

> `order` 在实际数据中与 `chapterNo` 同值，公开排序**不读它**；新增章照抄 chapterNo 即可。

## 2. 排序机制（两套）

- **读者侧**（`book/[id]/index.astro:68`）：公开书页**平铺**按 `pub_date` 升序，同日才比 chapterNo；**不按卷分组**（卷不传给主题）。阅读页上下章 = 此顺序前后项，并显示该章卷标（`i/[slug]/index.astro:73`）。
- **后台卷面板**（`extVolume.ts`）：卷内章按 chapterNo→pub_date→id；未归卷桶永远最后；卷间按显式 `volumeOrder`，否则首章 chapterNo，平手按首章 pub_date（按卷名拼音排会「第二卷」跑到「第一卷」前面，代码注释明确规避）。

## 4. 操作手册（以实际书为参照）

### 4.1 加一章——必做步骤

以「第三卷 归墟之门 第5章」为例（接现数据之后的正确写法）：

1. **定 `pub_date`**：`2026-03-05T09:00:00.000Z`（严格晚于现有最新 03-04；插队取中间时刻）。
2. **标题**：`第三卷 第5章 ×××`。
3. **正文**：编辑器写 HTML。
4. **卷键**：`第三卷 归墟之门`——**逐字复制已有卷名**。
5. **序号键**：`chapterNo: 5`（= 标题章号，同卷当前最大 4 + 1）。
6. **书键**：后台操作自动双写；脚本/API 必须两处都写 `J1jGJjUWeCz`。
7. 发布（status=1）或存草稿。

### 4.2 开新卷

首章 `volume` 写新卷名（如 `第四卷 ×××`）、`chapterNo: 1` 重新计数；卷自动按首章 pub_date 排在第三卷后。卷名一旦使用，后续章节必须逐字复制。

### 4.3 草稿归卷（本书现存的待办修复）

「第二卷 第1章 星河觉醒」（XhJgCh3Cccc）缺卷名与章号，需补：`volume: "第二卷 星河初现"`、`chapterNo: 1, order: 1`——补齐后即与实际第二卷序列 2-5 接续成 1-5，后台卷面板不再进未归卷桶。后台编辑该章填「卷 / 章号」两个输入框即可。

### 4.4 批量/脚本

**先停 `manage dev`**（独占 sqlite）。用通用技能 `novel-book-ops` 的 `scripts/add-chapter.mjs`（`--book` 接受任意书的频道 ID 或书名）：自动双写书键、校验卷名/章号/顺序（重号拒绝、标题章号不一致警告）；FTS 由触发器维护。批量更稳路径走公开 API（`.loose()` 直接透传 `_microfeed`）。

### 4.5 发布后必做检查

- [ ] 书键双写一致（新章 `book_id` 列与 `bookId` 标签都 = `J1jGJjUWeCz`）；
- [ ] 顺序：`/book/J1jGJjUWeCz` 新章夹在预期上下章之间；阅读页「下一章」正确；
- [ ] 卷：后台卷面板落位正确（卷名逐字一致）；阅读页卷标正确；
- [ ] 序号：chapterNo = 标题章号，同卷无重号；
- [ ] 搜索可命中新章正文；章与频道 `wordCount` 已同步。
