# ADR-0022: 版本门采用硬阻断而非软提示

**状态**: 已接受
**日期**: 2026-09-20
**来源**: 提升自 `.scratch/microfeed-rbac/adr/0009-gate-floor-vs-prompt.md`
**关联**: `0019` `0020` `0021`

## 决策

版本门采用**硬阻断**：低于 `minVersionInt` 的请求直接返回 `1006`，App 弹升级提示页。

## 理由

- 老 App 的界面与安全逻辑可能与新后端约定不兼容，软提示不足以隔离
- 硬阻断由服务端强制，App 无法绕过

## 后果

- 后端每次调高 `minVersionInt` 会强制所有低于该版本的 App 用户升级
- 后端需在灰度前确认目标版本用户占比可接受
- 与软提示的对比：软提示保留老版本可用，但对后端约定的持续演进形成负担
