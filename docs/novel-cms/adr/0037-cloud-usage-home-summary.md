# ADR-0037: 后台首页嵌入 Cloudflare 用量摘要（仅配额持有者可见）

- 状态：Accepted
- 日期：2026-10-20
- 决策人：用户 + 设计评审
- 关联设计：migration 0123（用量看板与该权限码的出处）、`src/server/rbac/seed.ts` 中该码「只授 super_admin」的授权范围注释（拍板 B1）、ADR-0009（看板权限与端点判定同源的口径）
- 本 ADR 来源：2026-10-19 起的 grill-with-docs 评审（两轮问题定稿）+ 写码前的两轴 code-review（结论回灌为最终方案）

## 背景

用户诉求：登录后台首页 `/[adminPath]/` 后，在「设置清单」上方直接看到 Cloudflare 用量（Workers / D1 / R2），不必再跳 `/[adminPath]/cloud-usage/`；理由是「这些数据只是只读数据」。

| 事实 | 位置 |
| --- | --- |
| 首页本身没有页级权限闸，登录即可见 | `src/pages/[adminPath]/index.astro` |
| `system:cloud-usage:read` 按拍板 B1 只授 super_admin，不进 `EDITOR_PERMISSIONS` | `src/server/rbac/seed.ts`（该码的授权范围注释） |
| 用量快照端点与详情页由同一个权限码把守 | `src/pages/[adminPath]/ajax/cloud-usage/index.ts`、`src/pages/[adminPath]/cloud-usage/index.astro` |
| 首页是一个 `client:only` 的 React 岛，无服务端取数 | `src/components/admin/home/AdminHomeApp` |
| 快照为只读聚合：一次 GET、`no-store`，失败只坏自己一页 | `src/server/admin/cloud-usage-handlers.ts` |

「只读数据所以人人可见」是一个诱人的推论，但它与 B1 冲突：B1 当初就是决定把这类基础设施用量数字只给 super_admin，只读性不改变这一点。可见范围怎么定、以什么方式定，是这次要回答的问题。

## 决策

### D1｜可见性在服务端预判，用权限判定本身，不用响应兜底

首页 frontmatter 调 guard 层的权限判定（`hasPermission`，与侧栏菜单可见性同源）算出布尔，作为 prop 传给首页岛。前端只认这个布尔。

不用「先渲染、发请求、遇 403 再隐藏」：那会给每个低权限账号在每次首页加载时发一次注定被拒的请求，并闪一下失败卡。也不把 `requirePermission` 的 `Response` 折成布尔：它叠加了账号门（未登录 / 禁用 / 设备吊销 / 改密待办），首页是公开入口，把这些折成「无权限」是语义混淆；账号门由请求链路负责，可见性只看权限位。

### D2｜无权限账号整块缺席，且不做任何指向详情页的入口

布尔为 false 时摘要组件不挂载、不发请求、不出提示。同时刻意**不做**「去详情页看看」这类链接：详情页对同一个码设闸，低权限账号点过去一样被拦，这种入口就是点不开的失效链接。要么真的可见，要么安静缺席。

### D3｜首页只放数值 + 额度 + 进度 + 倒计时，不放趋势图

密度上，首页是概览位：每个分区一张卡组加一个倒计时足够传达「额度用得怎么样」；七日月度趋势留给详情页。工程上，趋势图组件只留在详情页链路——摘要若从详情页组件反向引用，静态导入会把图表代码拖进首页 JS。倒计时、卡片网格、取数三件事抽成共享件，首页与详情页各有一份的写法不允许存在。分区级「整区不可用」的降级条同样是详情页专属：首页该区只留标题——首页承担「当前数字」的呈现，不承担降级诊断，要看原因去详情页。

### D4｜不做「查看详情」跳转链接

用户原话是「不需要再跳转别的页面」。摘要即终点；要看趋势与更详细的口径，用户自己会去详情页（对 super_admin 它一直可达）。为一个「便利」付一个与原始诉求矛盾的入口，不划算。

### D5｜新鲜度语义：挂载取一次 + 仅手动刷新，接受刷新前的陈旧

倒计时每分钟本地走格，但**不**触发重新取数；数字在一个会话内允许变旧，跨 UTC 日 / 月边界后倒计时停 0、数值保持旧值，直到手动刷新。这与详情页既有行为一致，且避免后台长期停留时反复外呼 Cloudflare。

## 后果

- super_admin 登录即见三分区用量；editor / readonly 的首页与此前**完全一致**，不多一个请求、多一个标记。
- 首页新增一次 Cloudflare 外呼（仅 super_admin 的每次首页加载），与详情页同量级；用量接口的失败语义不变（只坏摘要块）。
- 共享件倒计时定时器、卡片网格全仓各一份；引导态判定（含「账号 ID 不在设置页管理」的例外）也只有一份，首页与详情页共用。
- **已知边界**：会话内数字变旧、跨边界倒计时停 0，靠手动刷新恢复；不引入轮询。
- **未做**：给低权限账号的「用量只读副本」入口、首页趋势图、自动刷新——都在本次明确说「不」的清单上，后人要捡起其中任一项，先回来改这条 ADR。

## 验证口径

- 首页接线：`tests/unit/components/admin-home.test.ts` 锁布尔两种取值的缺席/在场、摘要恒在设置清单上方（清单完成与未完成两态）。
- 摘要渲染：`tests/unit/cloud-usage-summary-strip.test.ts` 以 fixture 快照直渲（本仓无 DOM 环境）锁 ready / 引导态三变体（含账号 ID 例外不给设置页链接）/ 失败卡与重试。
- 共享件：`tests/unit/cloud-usage-shared.test.ts` 锁取数纯判定、tick 与取数解耦（推进时钟不发生第二次请求）、卡片网格文案来源。
- 浏览器人工核对仍是最后一道：super_admin 登录首页见条带且在设置清单上方、刷新可取到新数、条带无图表；editor 登录首页无条带。

测试只写不跑，运行由用户手动触发 `.microfeed-gate-subset` 技能。
