# ADR-0041: 侧栏入口并入权限树，一棵节点表同时表达入口与授权

- 状态：Proposed（评估通过，待实现排期）
- 后续：角色管理页的实施分期与「侧栏预览」见 ADR-0042
- 日期：2026-10-21
- 决策人：用户 + 设计评审（grilling 四轮决策：合并形态 → 入口门码 → 首页去向 → 边界归属；D5 为 code-review 增补）
- 关联设计：ADR-0038（权限树自持节点表）、ADR-0039（双控制台单页）、`CONTEXT.md` 第 51/55/59 行三条术语（菜单可见性码 / 权限树宿主 / 菜单种子单向性）
- 本 ADR 来源：用户提问「权限树按角色权限分配，和菜单管理页是不是重复？菜单已是动态加载，能否直接取权限树渲染，去掉菜单管理页的二次管理」

## 背景

侧栏入口与授权结构目前由两张表分别维护，二者高度重合但字段互补，管理动作因此分散在两处，任何结构改动都要做两遍，存在漂移与不一致的空间。

| 事实 | 位置 |
| --- | --- |
| `ext_menu` 33 行 = 1 首页（`admin_home`，无门码）+ 6 分组（无门码）+ 26 叶子（有门码，去重后 25 个门码） | `migrations/` 内 `ext_menu` 种子 |
| `ext_permission_nodes` 桌面端 78 节点 = 6 分组 + 26 页面 + 46 码；App 端另有 15 行（1 分组 + 3 页 + 11 码），本无 `ext_menu` 对应物 | ADR-0038 建表，0127–0131 播种 |
| 分组同名 6/6；叶子与页面节点同名配对 **25/26** | 本地库实测 |
| 菜单独有 `rbac_audit`（path `rbac/audit`）；树独有 `media` | 同上 |
| `rbac` 与 `rbac_audit` 共用门码 `system:role:manage`，指向同一张权限页 | 同上 |
| `media:file:manage` 守卫 API 前缀 `/api/media_files`，没有对应后台页路由 | `src/server/api/api-permissions.ts:97` |
| 引进入口的门码分散在三处：菜单行 `permission_code`、页面守卫码、节点码；页面守卫绑定菜单行码的测试 5 条 | `tests/unit/admin-page-guards.test.ts` |
| 菜单管理自身也在合并射程内：`page_menu_management` 及其唯一门码 `system:menu:manage`（守卫菜单页与三个菜单端点，本地零角色持有） | `src/server/admin/menu-admin-handlers.ts:77/95/127` |
| 菜单管理侧代码约 2124 行；14 个源文件引用 `ext_menu`；35 个迁移、6 个 ADR 提过它 | 全仓扫描 |
| 用户补充核对：菜单库实为两级（6 分组 + 26 叶子），第三级是 `AdminSidebar` 的 `SUB_SECTION_BUILDERS` 代码注入、不入库 | `src/components/admin/AdminSidebar.tsx` |

用户由此给出核心判断：侧栏只要「分组下的二级页面」，与权限树的 page 层同层；合并因此只动 page 层。合并本质上要回答三个问题：入口放哪、入口门码怎么定、公开入口怎么办。

## 决策

### D1｜一棵节点表同时承载入口与授权，码层除退役项外不参与

给 `ext_permission_nodes` 的 `kind='page'` 节点补两个字段：`path`（页面 URL）与 `entry_code`（入口门码）。侧栏改从节点加载，`/admin/menu/` 先降级为只读视图跑一个版本，确认两侧栏一致后再下线。46 个 `kind='code'` 节点除 D5 退役项外一行不动——它们的职责只有授权勾选。

节点账：现有 26 个页面节点 = 25 个与菜单配对 + `media`；合并后减去退役的 `page_menu_management`（D5）、加上新建的 `rbac_audit` 节点，共 **26 个页面节点，其中 25 个带 `entry_code`，`media` 留空**。25 个配对节点的 `path` 与门码从菜单行平移（`menu_management` 除外，见 D5）；`rbac_audit` 挂在账户分组下，与 `page_rbac` 共用 `entry_code = system:role:manage`。

### D2｜入口门码用显式字段，不按规则推导

否决「优先取 `:read`、没有取第一个」的推导规则：规则是隐式的，将来给页面加码，入口门禁会悄悄变化；且 `page_rbac` 下根本没有 `:read` 码，仍需例外。显式字段让「这个入口给谁看」永远明确，也是唯一能干净表达「两个入口、一张权限页」的形态。

一次性人工确认的账（扣除退役的 `menu_management` 与留空的 `media`）：24 个配对节点中 **11 个单码自动填、13 个多码逐个定一次**；`rbac_audit` 复制 `page_rbac` 的门码。

### D3｜首页留代码常量，页面节点必须有门码才进侧栏

`admin_home` 不并入节点表：它无门控需求（所有登录用户可见）、位置固定（侧栏第一项）、且做成节点要放开「页面必须有码」的模型约束，还多一个误删除口。侧栏渲染时固定注入，模型保持纯粹——`entry_code` 为空的页面节点只挂码、不进侧栏（`media` 即此形态）。

### D4｜守卫判据从「恒等」放宽为「属于」

页面守卫与菜单行码的绑定测试（「守卫码 ≡ 菜单行码」，5 条）改为「守卫码 ∈ 该页面节点的码集」。合并前一个入口只有一个门码，恒等成立；合并后一个入口带一组码，「属于」才是正确语义。

### D5｜菜单管理自身随页面下线一并退役

`/admin/menu/` 没了，管菜单的权限也就没有意义：`page_menu_management` 节点与 `system:menu:manage` 码一并删除。该码的生效点只有菜单页与三个菜单端点（`ajax/menu/index`、`save`、`export`），全部随合并消失；本地零角色持有，远程实例若有授予随合并迁移清理。`rbac/seed.ts`、`Constants.ts`、`pc-interfaces.ts` 三处镜像同步移除，桌面端树从 78 行变 76 行，板子计数类断言随之更新。

## 备选

| 类别 | 备选 | 否决理由 |
| --- | --- | --- |
| 合并形态 | B｜保留 `ext_menu`，改为保存时单向派生 | 改动小、可回退，但两张表依然并存，多出「同步失败」这一失效模式，等于把两处维护换成同步漂移 |
| 合并形态 | C｜不合并，只加一致性校验 | 两处仍各自维护，出现「有菜单无节点、改名不同步」时告警。最省事，但不清混乱源头 |
| 门码形态 | b｜入口门码按规则推导（优先 `:read`） | 规则隐式，加码即漂移；`page_rbac` 下无 `:read` 码仍需例外（见 D2） |
| 门码形态 | c｜取消门码，「该页任一码被授权即显示」 | 只持写权限的角色会看到入口、点进去 403，与 44 个守卫点的现有语义冲突最大 |

## 后果

- 二次维护点归零：结构（分组/改名/排序）、入口门码、显示名三处并为一处。菜单侧净删 1974 行 = 2124 − 150（管理 UI 632 + 节点编辑器 394 + 树组件 257 + ops 548 + handlers 137 + 3 个端点 6），`menu.ts` 150 行改造保留；导出 SQL 回写通道 2 → 1。
- 新页面接入从「菜单行 + 节点 + 守卫码」三步变「节点 + 守卫码」两步。
- 一次性成本：14 个源文件；6 个测试文件 55 条用例重写或删除（`menu-admin-ops` 27 条与 `menu-admin-endpoints` 11 条整份是菜单逻辑；`admin-page-guards` 5 条改写判据）；`ADMIN_MENU_CODES` 27 条静态枚举随菜单码入库放宽类型。
- D5 退役链：桌面端树 78 → 76 行；`system:menu:manage` 从库、种子、枚举、接口清单四处消失；角色授予若有残留随迁移清理。
- 历史迁移不可重写：全新安装仍走「先建 `ext_menu` 再并入节点」的老路径，需追加一个合并迁移把种子补齐。
- 生产数据单向迁移：远程实例的 `ext_menu` 行（本地实测 33 行）并入节点；回退需反向迁移，菜单行的 `name_zh` / `name_en` / `path` / `permission_code` 必须可还原。
- 过渡期 `/admin/menu/` 只读，用户可能误以为仍可修改——页面要有明确提示。
- `CONTEXT.md` 三条术语随实现同批改写：「菜单可见性码」改称**入口门码**（锚点从菜单行改为页面节点）；「权限树宿主」锚点改为页面节点；「菜单种子单向性」改写为节点表版本。

## 验证口径

- 迁移探针：迁移前后 24 个进侧栏的配对行 `path` 与 `entry_code` 逐一比对，完全一致；`rbac_audit` 新节点门码与 `page_rbac` 相同。
- 守卫等价：`admin-page-guards` 5 条重写为「∈ 码集」后，与改造前「恒等」结论在全部 44 个守卫点上等价。
- 退役清理：`page_menu_management`、`system:menu:manage` 在库与种子、枚举、接口清单三处镜像中同时消失；桌面树 78 → 76 行。
- 孤儿守卫：`rbac-orphan-code-guard` 扩到「页面节点必须有父分组、码节点必须有父页面」，并对 `entry_code` 非空 ⇒ `path` 非空做约束。
- 侧栏快照：以真实库跑改造前后两侧栏行集（含顺序、显隐、计数），完全一致；`entry_code` 为空的节点不出现在侧栏。
- 授权口径不变：多角色并集、`readonly` 默认角色、App 端板子 11 码与 `system:app-capability:manage` 分区判定全部回归。
