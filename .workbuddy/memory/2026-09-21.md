## microfeed 接入极简 RBAC 方案（仅出计划文档，未执行代码）

- 分析 microfeed 现状：身份体系已基于 **Better Auth**（`src/server/auth/better-auth.ts` + `migrations/0002_better_auth.sql`）。`auth_user`(含 role/banned/banReason/banExpires) 与 `auth_session`(30天, token/ipAddress/userAgent/impersonatedBy) 已被 Better Auth 独占；登录节流（/sign-in/email、/verify-password 5/60s）、`admin()`/`passkey()` 插件、`revokeSessionsOnPasswordReset:true`、`disableSignUp:true` 已内置；公共 API 走独立 OAuth scope（READ/WRITE，`src/server/api/access.ts`），与后台 RBAC 无关。

## code-review 审核 RBAC（双轴，2026-09-21）

- 范围：`git diff HEAD -- src tests`（基点 `4db3fb4`）+ 未跟踪新文件（4 迁移 / `src/server/rbac/*` / `tests/worker/rbac.test.ts`）。用 `code-review` 技能起 Standards + Spec 两个并行子代理，本人逐条复核。
- **Spec（对照 T-01~T-16）真缺口**（已实证）：
  1. **系统域端点零覆盖**：T-10 DoD/§8.1 明确列 `webhooks/*`→`system:webhook:manage`、`account/*`用户管理→`system:user:manage`、站点设置→`content:settings:manage`、RBAC 管理页（新建）→`system:role/permission:manage`；实际只做了内容域（books/categories/volumes/feed）。`git status` 证实 webhooks/account/api/settings 等文件**完全未改**。且计划"排除项"**未**排除系统域 → T-10 标 done 属**高估**。
  2. **`banned` 分支未实现**：ADR D-010 步骤 1 要求 `auth_user.banned=1`→401；`src/` 全库零 `banned` 引用，`adminProtectionStatus` 只报 builtInLogin/cloudflareAccess。
  3. **版本门禁未进 middleware**：计划 §10 / ADR D-010 要求"martware 前置"；实测 middleware 未 import `requireAppVersion`、不读 `app-version`，只在 `requireRbac` 内对受控端点生效。
  4. **replay 顺序偏差**：ADR D-011 表写 `checkReplay` 应在"guard 之前"；实现是 version→permission→replay（replay 最后）。
- **误报（本人复核否定）**：子代理称"改 ajax 端点须同步 OpenAPI/ApiSchemas"——不成立：`/[adminPath]/ajax/*` 非公开契约，`src/shared` 内零 `ajax` 引用（公开契约是 `/api/*`，由 `ApiSchemas.ts`+`OpenApiDocument.ts` 定义）。
- **澄清**：`content:article:delete` 无 guard 非缺口——`items/[itemId].ts` 仅 GET，删除端点本就不存在（计划已注"编辑端点待定位"）。editor=7 权限含 `content:volume:read`，与计划 §8.1 注一致、与 T-11 字面列 6 条不一致（**spec 内部不一致**，非实现错）。
- **坏味道（judgement）**：① `requireRbac` 样板在 ~10 个 ajax 文件重复；② `seed.ts` 与 `0031` 权限目录双源；③ `guard.ts` `RbacLocals` 重复声明 `env.d.ts` 类型 + line 63 冗余 cast；④ 测试辅助 `clearRbacRows` 名不副实（还删 `auth_user`）。
- 结论：内容域实现扎实、升级安全红线全守；**系统域 + banned + 版本门禁/middleware 为先要补齐项**。
