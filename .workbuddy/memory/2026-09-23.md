## 诊断：普通用户只看到「首页」——是「未分配 RBAC 角色」，不是 bug、也与二级菜单无关

- **现象**：新建的「普通用户」（Better Auth `role="user"`）登录后台，侧栏只有「首页」。
- **完整链路**：`middleware.ts:453-463` 对已登录会话调 `resolveRbacContext(db, userId)` →
  `resolveUserPermissions`（`resolve.ts:18-27`）三表 JOIN `ext_user_roles ⋈ ext_role_permissions ⋈ ext_permissions`。
  该账号**没有 `ext_user_roles` 行** ⇒ 权限集 = ∅ ⇒ `readAdminMenu`（`menu.ts:77`）逐行 `rbacAllows(locals, permission_code)`：
  home 的 `permission_code = NULL`（`rbacAllows` 对 null 直接 true）⇒ 任何登录者可见；其余 **15 行都需命中权限码** ⇒ 全被过滤 ⇒ 只剩首页。
- **为何没角色**：`bootstrap.ts:101` 只给**首个用户**插 `r_super_admin`；`rbac-handlers.ts:582` 的 createUser 只写 Better Auth

### ⚠️ 后续 bug 修复：wangEditor 编辑后内容丢失（用户在上面集成之后报）

- **症状（user）**：历史 Quill/Markdown 正文 → 选 wangEditor → 编辑 → 保存（toast 成功）→ 重开仍是原内容。
  用户确认"**确实编辑了，内容丢了**"——是真实缺陷，不是"没编辑就保存"的预期行为。
- **根因（`RichEditorWangEditor/index.tsx` 用受控 `value={value}`）**：wangEditor-for-react@1.0.6 的 `<Editor>`
  内部有受控同步副作用（读 CJS 源码 `node_modules/@wangeditor/editor-for-react/dist/index.esm.js` 确认）：
  `useEffect(() => { if (editor && value !== curHtml) try { editor.setHtml(value) } catch(e){} }, [value])`。
  父级（EditItemApp/AdminRichEditor）每次 `setState`（`description` 更新、autosave 状态/新 extra 对象）都让 `value`
  重算并触发 `setHtml(value)`，把编辑器内容**重置回父级值**。当父级 `description` 因 React 批处理/严格模式时序
