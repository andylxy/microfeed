## 注册查重收口（用户名/邮箱都不能用已存在的）

用户要求「用户和邮件注册要核验，不能使用已存在的」。核查结果：

### 库层事实（远端 D1 实测）
- `auth_user`：`sqlite_autoindex_auth_user_1/2`（`email TEXT NOT NULL UNIQUE`，迁移 0002）+ `auth_user_username` 唯一索引（迁移 0039）。
- ⚠️ **SQLite 的 UNIQUE 是 BINARY 大小写敏感**，所以「大小写不敏感」只能靠应用层预检——这决定了预检不是可选项。

### 发现的真实缺口
**旧路径（只传 `email`/`account`、不带 `username`）没有邮箱查重**：重复地址落到 better-auth `createUser` 撞唯一约束 → 返回泛化 400「无法创建该账号」，而非清晰 409。

### 修复
- `createAdminRbacUser`：把用户名/邮箱查重**从各分支里提到分支之后统一执行一次**（原来只有新表单分支和 legacy 用户名分支有）。用户名 `lower(username) = lower(?)` → 409 `usernameTaken`；邮箱 `lower(email) = lower(?)` → 409 `emailTaken`（含占位邮箱，防止抢占他人登录槽）。
- 其他建号入口无需改：`bootstrap.ts` 由 `hasAdminOwner` 双重守卫；`password-setup.ts` initial 分支带 `NOT EXISTS (SELECT 1 FROM auth_user)`，都只在零用户时建首个管理员。

### 测试
- 新增 2 例：legacy 重复邮箱 → **409**（原为泛化 400）、新表单抢占他人占位邮箱 → 400。`rbac-user-profile` 27 → **29**，`rbac.test.ts` 68/68 无回归，合计 **97/97**。

## 落库前校验统一大小写不敏感（用户「不管大小写统一转小写校验」）

### 关键事实（查源码定论，别再凭印象）
- **登录侧本就不分大小写，无需改**：better-auth `internal-adapter.mjs:489` `findUserByEmail` 内部 `email.toLowerCase()`；用户名登录走插件 normalizer 小写归一。
- **SQLite 的 UNIQUE 是 BINARY 字节比较**，`Bob`/`bob`、`Bob@x.com`/`bob@x.com` 在库层算两条 → 大小写不敏感**只能靠应用层预检**。

### 改动
- `rbac-handlers.ts` 抽两个共享助手（放 `parseRbacUserId`/`mapBetterAuthError` 旁）：
  - `usernameIsTaken(db, username)` → `lower(username) = lower(?)`
  - `emailIsTaken(db, email, exceptUserId?)` → `lower(email) = lower(?)`（带 `exceptUserId` 时加 `AND id <> ?`）
- 全部落库前查重改用它们：建号（用户名/邮箱）、建号兜底 id 查找（`WHERE email = ?` → `lower()`）、后补用户名（原 `WHERE username = ?` 敏感）、改邮箱（保留 `id <> ?` 语义）。
- 目标：规则单一来源，调用点无法各自漂移。
